# 前端性能优化

性能优化不是简单“压缩代码”，而是让用户更快看到内容、更快完成操作，并减少布局抖动和交互延迟。

## 优化目标

- 首屏更快出现。
- 页面交互更快响应。
- 滚动和动画更流畅。
- 图片、脚本、字体资源更合理。
- 页面布局更稳定。

## 常见性能指标

| 指标 | 关注点 |
|------|--------|
| LCP | 最大内容多久显示出来 |
| INP | 用户交互响应是否及时 |
| CLS | 页面是否发生意外位移 |
| TTFB | 服务端首字节响应时间 |
| FCP | 首个内容多久显示 |

## 优化优先级

1. 先确认慢在哪里。
2. 再优化最大资源和最长任务。
3. 优先处理首屏、关键交互和高频页面。
4. 用数据验证优化前后变化。

## 常用手段

- 路由懒加载。
- 图片压缩、懒加载、指定宽高。
- 拆分大依赖。
- 静态资源缓存。
- 减少重复请求。
- 避免长任务阻塞主线程。
- 动画优先使用 `transform` 和 `opacity`。
