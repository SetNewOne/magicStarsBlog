# 系统稳定性

稳定性要求系统在流量变化、依赖故障、数据异常和代码变更时仍然可观察、可恢复、可控制。

## 稳定性目标

- 出错能发现。
- 问题能定位。
- 故障能隔离。
- 服务能恢复。
- 数据能修复。

## 核心能力

- 日志和链路追踪。
- 指标和告警。
- 超时和重试。
- 限流和熔断。
- 降级和兜底。
- 备份和恢复。

## 常见风险

- 接口没有超时，线程被一直占用。
- 重试没有限制，导致故障放大。
- 日志没有 traceId，问题无法串起来。
- 缓存击穿导致数据库压力暴涨。
- 依赖服务失败时没有降级。
