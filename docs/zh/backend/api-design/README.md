# 接口设计

接口是前端、后端和其他服务之间的契约。好的接口语义清楚、输入明确、返回稳定、错误可理解。

## 设计目标

- 资源命名清楚。
- 参数位置合理。
- 响应结构稳定。
- 错误码可定位问题。
- 支持分页、筛选、排序。
- 关键写操作具备幂等设计。

## 资源命名

```text
GET    /api/users
GET    /api/users/{id}
POST   /api/users
PUT    /api/users/{id}
DELETE /api/users/{id}
```

使用名词表达资源，用 HTTP 方法表达动作。

## 参数位置

| 参数类型 | 放置位置 |
|----------|----------|
| 资源 ID | 路径参数 |
| 搜索条件 | 查询参数 |
| 创建或更新数据 | 请求体 |
| 认证信息 | 请求头 |

## 统一响应

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

团队内应统一成功和失败的响应结构。
